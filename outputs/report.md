## 5. 自动诊断

1. **可靠性缺口（`card_formula`）**：pass@1 = 84.6% 看起来可以在灰度里用，但 pass^5 = 38.5%，缺口 46 个百分点。一次过和每次过是两个产品；上线门槛应该按 pass^k 定，不是 pass@1。
2. **场景级连乘（`card_injected`）**：行级 pass 52.0%，场级 pass 只有 10.8%（差 41 个百分点）。参照算一下：行级 95%、一场 4 行 → 场级约 81%。这就是必须按场报可靠性的理由。
3. **禁令违反（`naive_shot`：35.6% 的行）**：说明「不要喊」这类约束写在自然语言里是无效的，必须升级为结构化字段 + 硬阈值才可执行、可计数。
4. **给出公式才对齐（10.8% → 84.6%）**：同一份角色卡下，把参考算法原样交出，通过率跳升 74 个百分点。说明模型的短板不在「写参数」，而在「从台词读出内心情绪」——方法论含义是：这层能力该用检索/规则补，而不是指望 prompt。
5. **修复轮的性价比**：通过率 10.8% → 38.5%，代价是 tokens/场 2325 → 4636（+99%）。修复反馈只回传 L1 规则错误，不回传金标准数值——否则就是对着答案改错。
6. **阈值敏感性**：τ 从 0.5 扫到 1.0，`card_repair` 的 pass@1 跨度 85 个百分点。报告结论时必须给这条误差带，否则「我做到 85%」这种说法在换一个 τ 之后就会被打穿。
