# MangaDirector Harness

> 给「漫剧导演 Agent」做可靠性评测的框架：**答案不唯一的生成任务，怎么判卷？**

一个 Agent 把剧本片段编译成结构化的表演参数（强度 / 音高 / 语速 / 停顿 / AU / 禁令），
这个 harness 负责回答三个问题：**它演对了吗？每次都对吗？错了错在哪一层？**

### 页面（M2）

```bash

```

零第三方依赖（标准库 `http.server`），clone 下来就能跑，不需要装 Flask。
看效果可以直接带参数：`http://127.0.0.1:8770/?demo=1&compare=1&scaffold=card_formula&k=3`

一屏放三件事，而不是三个页面：

| 区域 | 是什么 | 给谁用 |
|---|---|---|
| 中栏分镜卡片 | 每句台词一张卡：10 维参数条、禁令徽章、导演备注、归因证据 | 创作者（真能照着做） |
| 右栏判卷 | 逐行逐字段命中、L1 错误、禁令违反、k 次分歧表 | 评测者（看错在哪一层） |
| 右栏顶部五臂对比 | 全量 13 场 × 5 scaffold 的 pass@1 / pass^k 条形图 | 面试官（一眼看到主结论） |

**参数条上那两条参考线是这一页最该看的东西**：紫色竖线是「AI 直觉版会演到几分」，
红色虚线是「禁令上限」。于是「模型想演 8.6、校准后只能演 6.4、红线在 6.5」
变成三个位置关系，而不是一行数字——这也是整个项目要解决的问题的视觉表达。

`/api/run` 一定返回**每次运行的原始镜头**，不只是聚合指标。只给一个 pass^k 数字，
等于又退回「只看分数不看分歧」的老路；页面要能让人看见这 k 次到底哪里不一样。

## 三个关键设计决策

### 1. 每个决策必须带 `evidence`，且必须是台词原文的子串

把「参数是否忠于原文」从主观判断变成**可确定性校验**的规则。
改写、复述、引用潜台词都算幻觉归因，直接判负，不进入容差比较。

这是整套判卷里性价比最高的机制：它让 L1 层完全不依赖金标准，
因此**不受「金标准是不是你自己」这一质疑的污染**。

### 2. 判卷分四层，能确定性判的绝不上模型

| 层 | 判什么 | 依赖金标准？ | 成本 |
|---|---|---|---|
| L1 规则 | schema、区间、evidence 归因、禁令是否被执行 | ❌ 不依赖 | ~0 |
| L2 容差 | 数值落容差、分类判等（部分分） | ✅ | 极低 |
| L3 VLM | 生成画面是否符合参数 | ❌ 独立证据源 | 中 |
| L4 人工 | 抽检校准 L3 | — | 高 |

禁令违反（"不要喊"却输出 intensity=9.5）在 L1 就能判死，
根本不需要调用 VLM——这既是方法论，也是成本决策。

### 3. 场景级 pass 要求**每一行**都过关，不用平均

平均会让一条演崩的台词被其他几条好台词稀释，而观众看到的恰恰是那一条。
`judge_scene` 因此用 `min` 语义（单测 `test_scene_pass_is_not_diluted_by_average` 守着这条）。

## 五个 scaffold 的消融意图

| scaffold | 给了什么 | 想回答的问题 |
|---|---|---|
| `naive_shot` | 只有台词 | 「AI 直觉版」到底错在哪 |
| `card_injected` | 角色卡 + 场景规范 + 契约 | 结构化上下文值多少 |
| `card_fewshot` | 再加 2 条金标准示例（跨作品） | 检索值多少 |
| `card_repair` | 再加校验失败重试 | 用 token 换可靠性值不值 |
| `card_formula` | 再把参考算法原样交出 | **瓶颈是「判断」还是「计算」** |

`card_formula` 是这套设计里最有信息量的一个臂：如果给了公式它就会做，
说明瓶颈不在「写参数」，而在「从台词读出内心情绪」——
那么这层能力该用检索/规则补，而不是指望 prompt 变大。

> **一条不可让步的纪律**：修复轮只回传 L1 错误，**绝不回传金标准数值**。
> 否则修复就变成对着答案改错，pass^k 被系统性虚高——这是评测污染在 agent 循环里的变体。

## 指标口径

- `pass@1`：单次通过率（场景级）
- `pass^k`：每场戏 k 次重复**全部**通过的比例 —— 生产可靠性指标
- **行级 pass**：不看场景连乘，用来暴露"行级 95% → 场级 81%"的衰减
- **禁令违反率**：按行统计，不按场（场会稀释问题）
- **CI**：按场景聚类的 Bootstrap（B=2000）。同一场戏的多行不独立，
  把行当独立样本会把 CI 算窄——项目一 `deff≈3.3` 那个坑的同构版本
- **k 次重复不当作样本量**：n 场 × k 次的有效样本量接近 n

每份报告还固定输出 **τ 敏感性**与**容差缩放敏感性**，
回答「换个阈值你这个结论还成立吗」。

## 已知局限（面试主动讲，别等人问）

1. **金标准就是参考实现本身。** `restraint.py` 里的常数是导演常识而非拟合结果，
   所以它不是一个"客观正确答案"，而是一个**可追溯、可复算、可被替换的基线**。
   缓解手段有三条：L1 不依赖金标准；容差敏感性必须报告；L3 VLM 提供独立证据源。
2. **容差是设计变量，不是实证结论。** ±0.8 的 intensity 容差约等于"半档"，
   是行业直觉，需要真实标注数据来标定（M4 之后的人工作业）。
3. **模板化场景不等于真实剧本。** 合成场景能控制因子、做消融，
   但不能替代真实剧本的分布——报告里必须分开写。
4. **`card_formula` 臂存在"送答案"嫌疑。** 它的作用是定位瓶颈，不是证明能力上限；
   真实实验里它应当作为**上界参考**，而不是拿来当成绩。
